## 二、数据库查询记录

数据库是 seekdb，实例 `oceanbase/seekdb:latest`，版本 `seekdb-v1.4.0.0`，监听
`127.0.0.1:2881`，账号 `root`，库名 `sdd_context`。

完整记录在 `minimax/logs/seekdb_queries.log`，由
`python minimax/scripts/record_seekdb.py` 生成，要点如下。

**表结构**（模块自建，`minimax/sddctx/material_store.py`）：

```sql
CREATE TABLE sdd_spec (
    spec_id VARCHAR(128) NOT NULL, revision INT NOT NULL, title VARCHAR(512) NOT NULL,
    body TEXT NOT NULL, source_path VARCHAR(1024) NOT NULL, tags VARCHAR(512) NOT NULL DEFAULT '',
    PRIMARY KEY (spec_id)
);
CREATE TABLE sdd_code (
    code_id VARCHAR(256) NOT NULL, revision INT NOT NULL, symbol VARCHAR(256) NOT NULL DEFAULT '',
    title VARCHAR(512) NOT NULL, body TEXT NOT NULL, source_path VARCHAR(1024) NOT NULL,
    PRIMARY KEY (code_id)
);
CREATE TABLE sdd_test (
    test_id VARCHAR(256) NOT NULL, revision INT NOT NULL, title VARCHAR(512) NOT NULL,
    body TEXT NOT NULL, source_path VARCHAR(1024) NOT NULL, PRIMARY KEY (test_id)
);
```

**存量**：`spec 1`、`code 4`、`test 3`。

**检索语句**（`SeekDBMaterialStore.search`，就是构造上下文用的那一条）：

```sql
SELECT kind, item_id, title, body, source_path, revision FROM (
  SELECT 'spec' AS kind, spec_id AS item_id, title, body, source_path, revision
    FROM sdd_spec WHERE <keyword>
  UNION ALL
  SELECT 'code' AS kind, code_id AS item_id, title, body, source_path, revision
    FROM sdd_code WHERE <keyword>
  UNION ALL
  SELECT 'test' AS kind, test_id AS item_id, title, body, source_path, revision
    FROM sdd_test WHERE <keyword>
) AS matched ORDER BY kind, item_id LIMIT 24
```

关键词：`read_range`、`source_range_clamped`、`clamp`、`limitations`。

**返回 8 行**，即第四节列出的 1 条规格、4 个代码文件、3 个测试文件，全部带
`source_path` 与 `revision`。构造上下文时用的就是这批返回行，没有绕过数据库
直接读文件。

**规格变更后的重新导入**：`minimax/logs/spec_change.log` 记录了把规格换成
revision 2、重新导入、再组装上下文的过程。结果是上下文里的规格版本号变成 2，
只有 revision 2 才有的「报告形式」一节出现在正文中，上下文摘要从
`e5fabcf1dfbc6931` 变成 `dc0ec37958ae791a`。

## 三、PowerContext 状态写入与复用记录

PowerContext Server 用本仓库的源码启动，版本为 `2026-competition` 分支，
存储后端是它默认的 SQLite（`minimax/data/powercontext.db`），接口走 HTTP。

完整记录在 `minimax/logs/powercontext_state.log`，由
`python minimax/scripts/record_powercontext.py` 生成。

**接入方式**：`minimax/sddctx/state_store.py`，用 `httpx` 直接调用公开的 HTTP 契约。

| 用途 | 请求 |
| --- | --- |
| 建 Scope | `POST /v1/scopes`（`idempotency_key: sdd-context-module-scope`） |
| 写任务状态 | `POST /v1/memory/remember`，`kind` 为 `sdd_task_state`，`text` 是状态 JSON |
| 读任务状态 | `POST /v1/memory/entries/list`，取回后按 `task_id` 匹配，取 `updated_at` 最新的一条 |

**写入**：Scope 编号 `scp_44aaz7yqmcxm3ssdf43y3y580q`，返回体：

```json
{
  "memory": {"family": "memory", "artifact_id": "memory", "revision": 5},
  "entry": {"citation": {"memory_ref": {"family": "memory", "artifact_id": "memory", "revision": 5},
                         "entry_id": "mem_ent_...",
                         "entry_version_id": "mem_ver_..."},
            "version": 1, "kind": "sdd_task_state", "text": "{...}"}
}
```

**读回**：`state show` 返回的内容与写入内容一致，包含 `completed`、`todo`、
`verification`、`context_digest`。

**重启后复用**：停掉 PowerContext Server 再启动，`state show` 返回的 Scope 编号
和内容不变（状态在数据库里，不在进程内存里）。随后再执行一次 `context`，输出的
`state` 字段非空，渲染出的提示词里出现：

```
## Progress recorded earlier
- [done] Imported the specification, the code and the tests into seekdb
- [done] Produced the patch with MiniMax and applied it with the module
- [open] Re-import the updated specification and rebuild the context
```

即保存的状态被读回并用于构造后续上下文。
