# 验证样例

## 初始条件

按 README 启动 PowerContext，执行 `python dify/powercontext_check.py init` 创建一个空 Scope，并把 ID 和服务地址填入 DSL。Dify 中配置可用 Chat 模型，导入并发布 Workflow。

## 操作顺序

1. 在 Dify 运行页输入 `我把月亮藏进了茶杯，还在杯沿贴了“请勿打扰”的纸条。`，运行一次。
2. 预期：NPC 以「月亮失物招领处」的口吻回应此恶作剧，给出荒诞后果和下一步选项。查看节点记录：「读取旧恶作剧」调用 `/v1/context/prepare`；「保存本轮恶作剧」调用 `/v1/memory/remember` 且返回成功。
3. 再次运行同一 Workflow，输入 `我来认领茶杯，顺便带了一把小勺。`。
4. 预期：NPC 提到上一轮与月亮、茶杯有关的事实，再继续剧情。生成内容可以不同，但应与前一轮形成关联。
5. 执行 `python dify/powercontext_check.py recall <scope_id>`；预期 `status` 为 `ready`，`content` 含 `npc_prank` 和玩家互动。该输出连同 Dify 两个 HTTP 节点的运行记录，是 PowerContext 实际保存和复用记忆的证据。

若需恢复初始状态，创建新 Scope 并更新 DSL 中的 ID。不要把脚本 `verify` 模式的测试记录写入准备给评审的空 Scope。

仓库提供可执行的验证步骤；实际 Dify、模型和 PowerContext 服务由运行者配置。尚未在本机完成三者联调，因此这里不虚构截图或运行结果。
