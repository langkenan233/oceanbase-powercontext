# 周边去哪儿

根据用户的位置与需求，提供至多 3 个有高德地点和步行路线数据支持的独立备选地点。评测环境已提供高德 MCP 工具；直接使用可用的地点搜索与步行路线规划能力，不要求用户提供 API Key，也不要自行配置或输出密钥。

## 处理请求

1. 从输入中提取城市、起点经纬度、地点类型或关键词、步行时间上限、推荐数量及排序偏好。经纬度传给高德工具时按工具要求使用“经度,纬度”顺序。以评测提供的起点坐标为准，不推测设备位置。
2. 推荐数量不超过 3；用户要求少于 3 个时遵从其数量。未给出数量时，最多推荐 3 个。只把用户明确提出的时间、地点类型及偏好当成筛选条件，不自行增加“正在营业”“安静”等限制。
3. 如果地点类型不明确，结合需求选择贴切的搜索词；仍无法确定时简要询问。对“近一点”等偏好，用实际步行路线的耗时与距离判断。

## 查询与筛选

1. 使用高德 MCP 的周边地点搜索（若工具名为 `maps_around_search`，使用该工具），以给定起点坐标为中心，按用户需要的地点类型或关键词查询。结合输入城市核对结果，排除明显不在目标城市或类型不符的地点。搜索结果为空或不足时，可调整同义关键词或适度扩大搜索范围；不要把搜索半径或地点直线距离当成步行时间。
2. 从搜索结果中去重，并保留可核对的地点名称、地址、POI ID 和目的地坐标。只对地点搜索实际返回的候选地点查询路线；缺少有效目的地坐标的候选不能进入推荐。
3. 对有希望入选的候选地点，逐个调用高德 MCP 的**步行路线规划**（若工具名为 `maps_direction_walking`，使用该工具）：每次都以用户给定的同一起点坐标为 `origin`，以该地点坐标为 `destination`。读取有效步行路线返回的距离与预计耗时；若返回多条路线，使用同一条路线中的距离和耗时，优先选耗时最短的有效路线。不要以直线距离、搜索结果距离、驾车或骑行时间代替步行路线数据，也不要自行按距离估算时间。
4. 仅保留地点类型符合需求且有有效步行路线的候选。用户给出步行时间上限时，仅保留路线耗时**不超过**上限的地点，边界值可以入选。按用户明确的偏好排序：例如“优先近一点”时优先按步行耗时升序，同耗时再按步行距离升序；没有明确排序偏好时，先考虑需求匹配度，再考虑步行耗时。推荐理由只能依据用户需求和已取得的地点、路线数据。
5. 最终取不超过用户要求且最多 3 个地点。各地点都是从同一起点出发的备选，不串成多站行程。不要为凑足数量加入超时、类型不符、路线未查到或数据有疑点的地点。

## 回答

用简洁列表或表格逐项提供：**地点名称、地址、预计步行距离、预计步行时间、推荐理由**。距离和时间使用步行路线返回的数据，换算单位时保持数值准确；不要把近似值写成精确实测值。推荐理由说明可核实的匹配点，例如地点类型符合、步行时间在限制内、在合格候选中更近。

- 若不足指定数量，说明只找到多少个符合条件的地点；没有符合条件的地点时如实说明，可建议放宽地点类型或步行时间限制。
- 地点搜索或步行路线查询失败时，说明哪一步无法核实；不编造地点、地址、距离或时间，也不把未核实的候选当成合格推荐。
- 对安静程度、排队情况、营业状态等工具结果没有证实的信息，标注“未核实”，不作肯定描述。地址缺失时标注“地址未返回”，不猜测补全。

不要额外导出 JSON、日志或测试材料；高德工具调用记录由评测平台采集。
